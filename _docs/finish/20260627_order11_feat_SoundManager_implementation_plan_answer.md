実装計画書（Proposed Changes）の内容を確認した。全体的なアーキテクチャは素晴らしいが、「ピンチ状態でのフィーバー突入時」の考慮漏れと、メソッドの引数名に設計意図が反映されていない問題があるため、以下の仕様を追加・修正して組み込むこと。

### 追加要件：メイントラック優先フラグ（isMainPriority）の導入
*   **フラグ名の変更**: `SoundManager.updatePinchVolume(lifeRatio, isMuted)` として提案されたメソッドシグネチャについて、第2引数の名前を単なる状態を示す `isMuted` から、設計意図を明確にする `isMainPriority` （メイントラック優先フラグ）へ変更せよ。
*   **懸念事項と適用条件**: 現在の計画では、ピンチ状態（LIFE規定値以下）のまま盤面が全色揃ってフィーバー（`fever`）に突入した場合、ピンチの音量制御（メイン低下・ピンチ上昇）が適用されてしまい、フィーバーBGMのカタルシスが削がれてしまう重大な仕様バグが存在する。そのため、`logic.js` 側で `isMainPriority` を `true` にして渡す条件を、「ホワイト/ブラックフェイズ時」に加え、「メインBGMが `fever` 状態の時」も必ず含めること。
*   **強制制御ロジック**: `updatePinchVolume` 内部において、`isMainPriority` が `true` の場合は、LIFE残量（lifeRatio）に関わらず強制的に「メインBGMを音量最大（100%）」かつ「ピンチBGMをミュート（0%）」とするよう制御せよ。プレイヤーが自らの手で色を揃えた「フィーバーの熱狂」やフェイズ移行の体験は、LIFE減少によるピンチ演出よりも常に優先される絶対ルールである。
