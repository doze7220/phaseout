# 実装指示書：キャラクターマネージャー（パズル層）の分離新設

アルファ版におけるキャラクターのスキルシステム実装に向け、インゲーム（パズル）とアウトゲーム（編成）の責務を完全に分離したアーキテクチャを構築する。
未来の技術的負債を防ぐため、以下の仕様に従って静的データと動的ロジックのモジュールを新設せよ。
※注意：本作の世界観設定ではキャラクターを「エージェント」と呼称するが、プログラムのクラス名や変数名において「Agent」という単語の使用は自律プログラム等との混同を防ぐため厳禁とする。必ず「Character」を使用すること。

## 1. 静的マスターデータ層の新設
*   **ファイル名**: `js/core/CharacterData.js` を新規作成。
*   **責務**: キャラクターの不変のマスターデータを定義する。
*   **実装内容**: 以下の仮キャラクター3名のID、名前、UI用画像パス（仮）、スキル名、最大チャージ量（仮の値でよい）をJSON（定数オブジェクト）として定義・exportすること。
    *   ID: `char_lino`, 名前: リノ (赤), スキル: フレイム・バースト
    *   ID: `char_cyan`, 名前: シアン (青), スキル: タイム・フリーズ
    *   ID: `char_elie`, 名前: エリー (緑), スキル: エメラルド・ヒール

## 2. パズル限定の動的ロジック層の新設
*   **ファイル名**: `js/core/CharacterPuzzleManager.js` を新規作成。（※絶対に `CharacterManager.js` としないこと。インゲーム限定モジュールであることをファイル名で明示する）
*   **責務**: パズルプレイ中のみ存在し、編成されたキャラクターの「現在のスキルゲージ（チャージ量）」を管理し、UIへ描画用データを提供する。
*   **実装内容**: 以下のメソッドを持つクラス（またはオブジェクト）を定義せよ。
    *   `init(partyIds)`: パズル開始時に呼び出される。引数で渡された編成データ（IDの配列）を元に、`CharacterConfig` から静的データを取得し、パズル用のインスタンス変数（各キャラの現在のゲージ量=0）とマージして初期化・保持する。
    *   `getSlotData(slotIndex)`: フッターUI（`FooterUIManager.js`）から毎フレーム呼び出されるGetter。指定された枠（0〜2）に編成されているキャラクターの画像パス、名前、スキル名、現在のゲージ量、最大ゲージ量などをまとめて返す。
    *   `addCharge(color, amount)`: パズル盤面で宝石が消された際に呼び出され、該当するキャラクターのスキルゲージを加算するロジックのガワ（プレースホルダー）を作成する。
    *   `reset()`: パズル終了時（リザルト移行時）に呼び出され、内部のゲージ情報を完全に破棄する。

## 3. GameState の編成状態拡張
*   **ファイル名**: `js/core/config.js`
*   **実装内容**: `GameState` の初期値定義に、現在の編成状態を保持するプロパティを追加する。
    *   `party: [ "char_lino", "char_cyan", "char_elie" ]` （※アルファ版ではこの3名のID固定とする）

上記要件を満たすよう、ファイルの新規作成とコードの構築をフルスロットルで実行せよ。
